# Engineering decisions

- The supplied workspace was empty. The complete specification was copied unchanged from Downloads; no prototype archive, old APK, source, preferences, or matching signing material was available. Nothing was replaced or removed.
- Native Kotlin, Compose Material 3, Room, coroutines/Flow, ViewModel, and DataStore. No WebView app or custom DEX tooling. The pure `core` JVM module owns chronology, graph math, archive validation, projections, and interchange.
- AGP 8.11.1 / Gradle 8.13 / JDK 17 / compile and target API 36 are a compatible pinned combination. They are deliberately not independently upgraded to every newest release. [Official compatibility table](https://developer.android.com/build/releases/agp-8-11-0-release-notes).
- The normalized record registry uses a row per model identity, separate field rows, reference joins with role/ordinal, and per-slot typed temporal expressions. This combines many conceptual tables without combining their identities or storing a whole world as a JSON blob. See DATA_MODEL.md.
- All root and secondary record editors are functional and use the same schema-driven controls. Epochs additionally have a dedicated read-oriented Codex, chronology, state, and legacy view. Raw JSON is never the ordinary editing interface.
- Restores default to new worlds. Same-identity replacement requires an explicit checkbox and confirmation, an internal pre-restore archive, staged immutable files, and one database transaction.
- Permanent erasure preserves typed identity tombstones for incoming references and retains an internal recovery archive. This avoids automatically deleting other people's authored relationship explanations or creating dangling graph endpoints. No automatic file garbage collection runs.
- Snapshots default to unlimited retention; per-world settings can retain 10, 50 or 100 checkpoints, pruning on the next checkpoint. Board undo is a separate bounded 100-command session history. Files are never automatically garbage-collected.
- Public history is an allowlisted projection of explicitly included account prose and explicitly shared, account-selected sections. Canonical titles, prose, private IDs, captions, and metadata have no fallback into this projection.
- Search uses FTS4 with a parameterized Unicode substring fallback. FTS tokenization is not linguistic segmentation for every script. Search is scoped by world at the query layer.
- Windows Kotlin compilation runs in-process with a single-use Gradle daemon after observed compiler/build-daemon JAR locks. This is a development-tool workaround, not an Android runtime behavior.
- App ID is `app.nodenote.worldbuilder.debug` for tests. No `legacyUpgrade` variant is provided without a matching old certificate. After USB debugging authorization, test updates were installed and launched on the owner's Android 14 phone without clearing data. Instrumentation remains isolated from the personal package.
